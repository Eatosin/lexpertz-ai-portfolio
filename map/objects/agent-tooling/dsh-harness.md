# DSH harness

DeepSeek Harness surface for the same instructions OpenCode reads: `.dsh/skills/` plus an optional profile bundle at `.dsh/harness/`. No build step, and no plugin in the common path.

## Why this shape

DSH discovers skills from fixed roots, not a config file: `.dsh/skills/` and `.agents/skills/` from the repo root, plus `AGENTS.md` for workspace instructions. So the repo keeps one instruction source per surface and bridges the OpenCode-only roots with committed aliases instead of duplicating skills. Commands and subagents cannot be files in DSH — slash commands are plugin-owned and subagents are agent presets — so both are ported as skills: commands become user-invocable skills (`disable-model-invocation: true`), personas become model-invocable skills.

## Shape

- Aliases (17, committed symlinks): `.dsh/skills/<id>` → `skills/<id>` (11) or `.opencode/skills/<id>` (6). DSH scans direct children only, so each skill needs its own alias; a link to a whole root would be invisible.
- Command skills (12): `.dsh/skills/<command>/SKILL.md`, user-invocable. `/plan` became `/plan-feature` because DSH's plan-mode command owns `/plan`.
- Persona skills (8): `planner`, `code-reviewer`, `security-reviewer`, `tdd-guide`, `build-error-resolver`, `doc-updater`, `refactor-cleaner`, `harness-optimizer` — model-invocable, loaded in the current session.
- Vendor blog aliases (32): generated by `.dsh/bin/link-vendor-skills.sh`, gitignored, off by default.
- `.dsh/harness/`: Cordis bundle with 8 agent presets (read-only ones set `tool-fs` `write`/`edit`/`applyPatch` to false) and the `shadcn` + `resend` MCP rows. Installed in the DSH `web` profile on 2026-11-05 as a linked package, so the presets show in new sessions and edits here apply on reload.
- `.agents/skills/` needs nothing: it is already a default DSH root.

## Connected to

- **owns:** `.dsh/`
- **owned-by:** none — the DSH surface is additive
- **joins:** [harness-config](harness-config.md) still owns `opencode.json`; the OpenCode roots it lists are aliased here
- **looks-like-but-is-not:** the aliases are not copies. Editing `skills/api-design/SKILL.md` changes both harnesses.

## If you change this

- **Hits:** a malformed `SKILL.md` under `.dsh/skills` disappears silently (description required, kebab-case name, boolean invocation flags); renaming a skill folder breaks `/` invocation; installing the bundle changes every session in the DSH profile, not just this repo.
- **Does not hit:** the site build, `src/`, `content/` — and OpenCode keeps working from its own discovery.

## Surfaces

| Surface | Role |
|---|---|
| DSH sessions (web, headless) | discover `.dsh/skills` and `.agents/skills`, load `AGENTS.md` |
| `.dsh/harness/` | optional profile presets and MCP |
| OpenCode | unaffected; reads `.opencode/` + `opencode.json` |
